# Recipes App

Мобильное приложение на Flutter для просмотра рецептов с поддержкой поиска, фильтров, кэша, офлайна и переключения темы.  
Реализовано по требованиям тестового задания.

---

## 🚀 Функциональность

### 1. Загрузка рецептов с API
- Загрузка при старте приложения  
- Поддержка retry  
- Полная обработка ошибок  
- Стабильность при неправильном `content-type` (сервер отдаёт HTML вместо JSON)

### 2. UI состояния
- Loading  
- Error (с кнопкой «Повторить»)  
- Empty  
- Offline (если данных с сервера нет, но есть локальный кэш)  

### 3. Поиск и фильтр
- Поиск по `title`, `ingredients_one`, `ingredients_two`  
- Фильтр:
  - «Только с изображениями»
  - Сброс фильтров  
- UI вынесен под AppBar

### 4. Экран деталей рецепта
- Изображение  
- Полный текст  
- Ингредиенты  
- Шаги (обработаны через отдельную модель)  
- Энергетическая ценность  

### 5. Кэш и офлайн-режим
- При успешной загрузке рецепты сохраняются в SharedPreferences  
- При запуске без сети отображается последняя сохранённая версия  
- Картинки кэшируются через `cached_network_image`

### 6. Пагинация
- Клиентская (по 10 элементов)  
- Догрузка при скролле  
- Индикатор «loading more»

### 7. Анимации и UX
- Плейсхолдеры изображений  
- Drag-handle у фильтра  
- Анимация карточек платформенная (Ink + gestures)

### 8. Тема (светлая/тёмная)
- `ThemeCubit`  
- Автосохранение выбранной темы  
- Тумблер в AppBar

## ⚠️ Особенности API

API постоянно возвращает `content-type: text/html`, иногда gzip, иногда HTML вместо JSON.  
В проекте реализован **универсальный обработчик данных**, который:

- обнаруживает HTML  
- пытается безопасно декодировать JSON  
- корректно обрабатывает ошибку  
- не ломает приложение  
- позволяет работать с офлайн-кэшем  

---

## 📄 Ограничения

- Сервер нестабилен и некорректно отдаёт JSON  
- Поскольку API отдаёт HTML, в приложении отображается ошибка и кнопка Retry — это корректное поведение по ТЗ
